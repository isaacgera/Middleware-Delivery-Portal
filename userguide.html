Middleware Delivery Portal

User Guide — Phase 1 (Estimation & Planning)

MDP is a shared web app for estimating and costing middleware work. You sign in, build Requests from an approved Menu Card, and produce customer-ready PDFs — all with governance, versioning and a full audit trail. This guide walks through everything you can do.

Roles: a feature marked Both is available to everyone; Admin means Administrator-only. Administrators can do everything a Delivery Manager can, plus manage Menu Cards and view the full audit log.

1. Signing in

  1. Open the portal’s address in your browser.
  2. Enter your username and password and sign in.
  3. Your session stays active while you’re using it and signs you out automatically after a period of inactivity (about 30 minutes) — just sign in again.

You can change your own password from the account controls. If you’re locked out or need an account, ask an Administrator.

1a. Installing MDP as an app (optional)

MDP runs in your web browser, but you can install it as a desktop app — it then opens in its own window (with the MDP icon, no address bar) and gets a Start-menu entry, just like any other program. It’s the same MDP either way; installing is purely for convenience.

How to install (Edge or Chrome):

  1. Open the MDP web address your administrator gave you (the normal link you sign in with).
  2. Look at the right-hand end of the address bar for a small install icon (a monitor/screen with a down-arrow). Click it.
    No icon? Use the browser menu instead — Edge: ⋯ → Apps → “Install Middleware Delivery Portal”. Chrome: ⋮ → “Install Middleware Delivery Portal” (or Cast, save and share → Install page as app).
  3. Confirm Install. MDP opens in its own window and is added to your Start menu; you can pin it to the taskbar.

Good to know: MDP is a shared, server-backed tool, so the installed app still needs the network and your sign-in — it is not an offline copy, and it holds no data on your machine (the data lives safely on the MDP server for everyone). To remove it later: open the installed app → ⋯ → Uninstall, or use Windows Installed apps.

Note: you install from the running MDP link, not from the code repository (GitLab/GitHub) — those hold the source code, not a runnable app.

2. Finding your way around

The top bar has the navigation (Home, Requests, Catalogue, Dashboards, Analytics, plus Menu Cards and Audit for admins), your name and role, a sign-out button, and a theme toggle. Home shows a quick API/health check so you know the app is connected.

3. The Product Catalogue Both

The Catalogue shows every service in the currently active Menu Card.

  • Component / Size pills — click to filter (e.g. MQ, XL); combine them; “All” clears that row.
  • Search — type anything (a word from a service, a size, a cost) to match across all columns.
  • Open a row (click, or focus with the keyboard and press Enter) to see the full detail: Story Points, ATOM, PD, TCS/FTE/Total cost, and any scope / assumptions / exclusions.

The Catalogue is read-only — it’s the master price list. You turn its services into costed lines inside a Request (next section).

4. Requests — the core workflow Both

A Request is one estimate. Open Requests for the list; use the search box, the per-column filters, the created-date range, and the pager to find one. Click a row (or its Open link) to work on it.

Create a request

  1. Click Add Request.
  2. Fill the mandatory fields: JIRA Reference (your own unique handle — it must not already exist), Summary, Customer, CFU, Approver, and the Component + Size. Optionally add External Ref, IP Code, IO Reference and Remarks.
  3. Click Create. The request opens, pinned to the active Menu Card.

The Component + Size you pick scope the request — you can only add catalogue services that match them. This keeps every line consistent with the estimate’s shape.

5. Line items & live totals Both

  1. On the request, click Add from catalogue. The picker shows only the services matching this request’s Component + Size.
  2. Click Add on a service. It becomes a line, and its figures are snapshotted — locked in at that moment.
  3. Change a line’s Quantity and the totals update live. Use the duplicate (⧉) or delete (✕) buttons on a line as needed.

Why snapshots matter: if the Menu Card is re-imported or changed later, an existing request’s numbers never move. What you quoted is what stays. The totals strip (Lines, PD, Story Points, ATOM, TCS, FTE, Grand Total) always reflects the current lines, calculated exactly.

6. Status, Archive & Cancel Both

Use the Status dropdown on a request to move it through New → Pending → Approved → In Progress → Done. You can set any status at any time — there’s no forced order.

  • Archive — tucks a request out of the default list (find it again with Show archived). Un-archive to bring it back.
  • Cancel — for a request that’s stopped. You can’t cancel one that’s already Done or Archived, and a cancelled request must be revived to an active status before it can go to Done/Archived.

7. Exporting a customer PDF Both

From a request’s Actions menu:

  • Preview — opens the estimate PDF in a new tab (nothing is recorded).
  • Export — generates the PDF and delivers it: a download on desktop, or the share sheet on mobile (WhatsApp, Save to Files, etc.). Each export is recorded in the audit log.

The PDF is the customer-facing document — a clean summary plus the cost figures, carrying the Forjé footer. (That footer is intentional on the PDF; it’s hidden if you ever just print the web page itself.)

8. Cloning & editing a request Both

  • Clone (Actions menu) makes a full copy — a fresh reference, a derived -COPY JIRA reference, status reset to New, and every line copied with its snapshot figures intact. The copy opens so you can rename its JIRA reference.
  • Edit (Actions menu) changes the header fields. Note: Component and Size are locked while any lines exist (remove the lines first if you must change them — otherwise the lines wouldn’t match).
  • Delete removes the request (with a confirmation). This can’t be undone.

9. Dashboards Both

The Dashboards view summarises all requests under a filter bar (CFU / Component / Status / date range). You get headline KPI cards (total cost with TCS/FTE split, request counts, USP, active CFUs), charts (donuts for product & CFU share, a monthly timeline, bars for status & size) and revenue-share tables. Change a filter and everything re-scopes. You can Export the current filtered summary as PDF or CSV.

10. Analytics Both

The Analytics view reconstructs how work actually flows, from each request’s history:

  • Throughput — requests reaching Done per month.
  • Cycle time — how long from Created→Done (and Approved→Done).
  • Dwell & aging — how long requests sit in each status; which open ones are aging past a threshold you can set.
  • Run-rate — a plain, honest projection of how long the committed backlog will take, with the assumptions shown. It’s a guide, not a forecast.

Use Filter mode to scope the metrics, or Compare mode to break them down by component, size, CFU or customer.

11. Menu Cards Admin

Administrators manage the master price list under Menu Cards.

  1. Import the Menu Card .xlsx (set the financial year). MDP parses the component tabs and stages it as a Draft, showing counts and any warnings.
  2. Review the draft, then Activate it. Activation is atomic: the new version becomes Active and whatever was active is Archived — there is always exactly one active card.
  3. You can re-activate an archived version, edit a version’s label / financial year, download the original uploaded file, or delete a version (unless it’s active or referenced by a request).

The as-imported effort/cost values are never editable in place — to correct them, re-import a corrected workbook. Existing requests keep their snapshots regardless.

12. Audit / History

  • Admin Audit — the full log across all users, filterable by action, user and date range.
  • Both History — for non-admins, your own activity only.

Logged events include sign-in/out, Menu Card upload & activation, and request create / modify / delete / export. The log is append-only — entries are never edited or removed.

13. Tips, themes & accessibility

  • Theme — the toggle (top-right) cycles follow-system / light / dark and remembers your choice.
  • Keyboard — everything is operable by keyboard: a “Skip to main content” link on first Tab, focusable rows and menus, and visible focus outlines.
  • Screen readers — actions like changing a status or adding a line are announced; icon-only buttons are labelled.
  • Mobile — the layout adapts to small screens; the PDF export uses the native share sheet.
  • Your data is safe — figures can’t drift (snapshots), the active Menu Card is always singular, and every change is audited.
